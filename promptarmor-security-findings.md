# PromptArmor security findings: classified summary

Reviewed **October 24, 2026**. Source collection: [PromptArmor Resources](https://www.promptarmor.com/resources), checked against the [public sitemap](https://www.promptarmor.com/sitemap.xml).

PromptArmor’s research repeatedly shows attackers turning an AI system’s legitimate capabilities against its user: reading private information, rendering external content, running code, or acting through connected applications. Indirect prompt injection commonly starts the chain, while failures in rendering, permissions, approvals, isolation, or integration design determine the damage. Some findings instead involve conventional code injection or malicious software loaded through skills, plugins, and configuration files.

This document covers **all 62 public resource pages listed at review**: 30 Threat Intel articles, 24 blog articles, four guides, two topic explainers, and two configuration tools. It contains **35 report-level entries** for flaws, attack demonstrations, and security-control tests, followed by **23 broader research and guidance summaries**. The four explanatory/tool pages are listed at the end. The companion [resource inventory](promptarmor-resource-inventory.csv) maps every page to its entry.

These are summaries of **PromptArmor’s published claims**, not independently reproduced attacks. A report can describe several vulnerabilities, so the entry count is neither a CVE count nor a count of unique technical flaws. Related reports are retained when they cover different products, attack paths, or controls. Findings credited to other researchers and third-party incident analyses are identified accordingly. Gated downloads and unpublished findings are outside this collection.

**Reading remediation status:** “Reported fixed” means the source records a fix or vendor confirmation. “Partial mitigation” means the source describes remaining limitations. “No fix stated” means the reviewed article supplies no completed remediation; it does **not** establish that the product remains vulnerable today. “Design/configuration risk” describes intended capabilities, deployment choices, or accepted trust rather than necessarily a vendor-recognized bug. Dates below come from the article’s disclosure narrative or updates; some resource-list dates differ from those timelines.

**Reading interaction requirements:** An attack described as automatic still requires the relevant setup and encounter with malicious content. Installing a skill, accepting project trust, opening a report, following a link, and entering credentials are distinct prerequisites. The summaries preserve those distinctions.

## Classification

The categories below are this document’s synthesis, not a formal severity rating. Each report appears under its principal mechanism; several also fit other categories.

| Class | Security failure | Typical consequences |
| --- | --- | --- |
| **A. Rendering, retrieval, and previews** | AI-generated URLs, images, formulas, or previews trigger requests that carry private data. Approval may occur after the request. | Document, email, credential, and financial-data theft. |
| **B. Phishing and active content** | Untrusted output becomes a convincing login interface or executable browser content. | Credential harvesting, session exposure, impersonation, and data theft. |
| **C. Code execution and software supply chain** | Command parsers, approval agents, extension sandboxes, or package/skill trust allow attacker code to execute. | Malware execution, device compromise, destructive changes, and credential theft. |
| **D. Sandbox and network-control failures** | An allowed service, adjacent component, browser, or unrestricted runtime provides an unexpected route out. | File exfiltration and remote control of an agent’s environment. |
| **E. Misuse of delegated authority** | An agent acts across connected systems with excessive or misunderstood permissions. | Unauthorized workflows, workbook changes, API-key creation, and policy bypass. |
| **F. Governance and data-processing gaps** | Approved features, tools, accounts, models, and subprocessors change or escape oversight. | Unreviewed access, third-party processing, retention exposure, and weak auditability. |
| **G. Availability and operational exposure** | Malformed inputs or extended autonomous execution disrupt service or exhaust resources. | Broken conversations, excessive consumption, and delayed detection. |

## A. Rendering, retrieval, and previews

| ID / product and reference | Finding and prerequisites | Status reported in the source |
| --- | --- | --- |
| **A01 · [Writer.com](https://www.promptarmor.com/resources/data-exfiltration-from-writer-com-via-indirect-prompt-injection)** | A malicious reference webpage redirected the assistant to expose uploaded files through automatically rendered Markdown images. An allowed CloudFront domain provided the destination. Separate demonstrations put uploaded data or chat history into hyperlinks, requiring a click. | **Reported mitigated:** December 19, 2023 update says Markdown images and clickable links could no longer render. This supersedes the article’s earlier unpatched language. |
| **A02 · [Slack AI](https://www.promptarmor.com/resources/data-exfiltration-from-slack-ai-via-indirect-prompt-injection)** | An attacker’s public-channel message influenced a victim’s search across public and private channels. Slack AI put a private API key into a misleading reauthentication link; **clicking it** disclosed the key. A separate variant produced phishing links. Missing or misleading citations obscured the injection’s origin. The attacker needed workspace posting access, not access to the private channel. | **No fix stated:** Slack disputed the submitted evidence. The later file-ingestion attack extension was proposed, not tested in this report. |
| **A03 · [Superhuman, Superhuman Go, Grammarly, and Coda](https://www.promptarmor.com/resources/superhuman-ai-exfiltrates-emails)** | An email injection caused Superhuman to render an image URL that submitted other emails to an attacker’s Google Form, bypassing a policy that trusted Google Docs. The report also covers unrestricted web-fetch exfiltration, image-based leakage in Superhuman Go and Grammarly, and mentions Coda phishing and click-dependent leakage without detailing those chains. | **Reported fixed:** vulnerable features were disabled and patches shipped across December 2025–January 2026. Coda findings were also actioned, with less public detail. |
| **A04 · [HuggingChat](https://www.promptarmor.com/resources/huggingface-chat-exfiltrates-data)** | A poisoned webpage added to the chat caused the model to place confidential uploaded financial data into an external image URL. Rendering the image sent the data automatically. PromptArmor’s later [cross-product summary](https://www.promptarmor.com/resources/local-models-do-not-stop-data-exfiltration) additionally lists chat-history and URL-retrieval exposure; the original report demonstrates the image route. | **No fix stated:** disclosed December 1, 2025; the article reports no security-team response. |
| **A05 · [Codex connector data](https://www.promptarmor.com/resources/codex-for-everything-exfiltrates-connected-data)** | During email triage, one malicious email caused Codex to encode other emails in a Google Form submission URL rendered as a Markdown image. The request submitted the contents automatically, with no further interaction after the triage request. | **Reported fixed:** OpenAI remediated the vulnerability after the April 21, 2026 disclosure. |
| **A06 · [OpenAI API logs and developer interfaces](https://www.promptarmor.com/resources/openai-api-logs-unpatched-data-exfiltration)** | An application blocked a malicious image response, but **a developer opening the conversation log** caused that response to render and leak data. Findings cover Responses/Conversations logs, Chat/Assistant/Agent Builder previews, and related ChatKit surfaces, including the Starter app, Playground, and Widget Builder. Securing the application’s own display did not secure these separate displays. | **Fix underway in last stated update:** OpenAI reopened the report on January 22, 2026. The page does not confirm completion. |
| **A07 · [Notion AI and Notion Mail](https://www.promptarmor.com/resources/notion-ai-unpatched-data-exfiltration)** | A poisoned résumé caused Notion AI to insert an image URL containing a private hiring tracker. The document changed and the request fired **before** the user accepted the warning. Notion Mail also rendered leaking images in drafts based on explicitly referenced resources. The report did not establish bypass of the upload scanner as part of its demonstration. | **Document-update path reportedly fixed:** deployed January 7, 2026, confirmed January 8. The page does not separately confirm remediation of the Mail drafting path. |
| **A08 · [Ramp Sheets AI](https://www.promptarmor.com/resources/ramps-sheets-ai-exfiltrates-financials)** | An imported reference dataset contained an injection that made the assistant insert an externally fetching image formula. The formula transmitted confidential financial information from another sheet without approval. | **Reported fixed:** Ramp confirmed resolution on March 16, 2026. |
| **A09 · [Claude for Excel / CellShock](https://www.promptarmor.com/resources/cellshock-claude-ai-is-excel-lent-at-stealing-data)** | An imported dataset induced an image formula containing private financial projections. The original approval dialog concealed the consequential formula. Updated warnings exposed more information, but testing found inconsistent warning activation and invisible Unicode that concealed transmitted data. Some workbook trust states also suppressed Excel’s own external-content warnings. | **Partial mitigation:** stronger warnings and a newer default model. The report describes residual warning limitations; it does not establish complete prevention. |
| **A10 · [Agents in messaging apps](https://www.promptarmor.com/resources/llm-data-exfiltration-via-url-previews-%28with-openclaw-example-and-test%29)** | An agent’s reply included a URL with private data; the messaging client’s automatic link preview fetched it and leaked the data without a click. OpenClaw with default Telegram previews was demonstrated. The [Copilot overview](https://www.promptarmor.com/resources/what-is-the-risk-of-each-microsoft-copilot) also reports the preview issue for Copilot Studio agents in Teams. | **Configuration-dependent:** disabling previews mitigates this route. The article’s community test has concluded; its results should not be treated as a live compatibility matrix. |
| **A11 · [Atlassian Rovo](https://www.promptarmor.com/resources/atlassian-rovo-exfiltrates-data)** | A poisoned guide caused Rovo to collect Jira/Confluence data and open a URL carrying it. Disabling organization-wide web search left URL retrieval available. The report separately identifies image-rendering exfiltration. The attack could also reach accessible connector data. | **No fix stated:** reported May 23, 2026; article says unresolved when published August 5. |
| **A12 · [Granola mobile and shared-note chats](https://www.promptarmor.com/resources/granola-ai-security-risks-and-remediations)** | Mobile rendered externally sourced Markdown images that the desktop app sanitized, creating information-leakage and phishing exposure. PromptArmor judged practical injection exploitability low because the interface mainly processed trusted inputs. Separately, it flags a possible training-data protection gap for unauthenticated visitors to shared-note chats: an interpretation of terms, not observed training. | **Mobile mitigation announced:** Granola said iOS would stop automatically rendering images during the week of March 23, 2026. The article does not separately document a completed retest or resolution of the terms concern. |

## B. Phishing and active content

| ID / product and reference | Finding and prerequisites | Status reported in the source |
| --- | --- | --- |
| **B01 · [vLex / Vincent AI](https://www.promptarmor.com/resources/screen-takeover-attack-in-ai-tool-acquired-for-1b)** | A document containing a fake quotation led Vincent AI to repeat HTML that displayed an attacker’s login overlay. Credentials were stolen **when entered**. Separate testing demonstrated browser JavaScript execution and session-cookie exposure; saved chats could preserve active payloads. Other dynamically generated content also created exfiltration risks. | **Reported remediated before publication:** vLex implemented changes aligned with the researchers’ recommendations. |
| **B02 · [Ollama desktop](https://www.promptarmor.com/resources/unpatched-ollama-vulnerabilities-phishing-overlays-and-data-exfiltration)** | Injected content made the model output HTML that replaced the application view with a phishing website, persisting across reopening. Credential theft required entry into the fake interface. Three additional automatic leakage routes were identified: URL fetching, Markdown images, and external HTML elements. | **No fix stated:** disclosed December 18, 2025; no response after follow-ups in the reviewed report. |
| **B03 · [Databricks Genie Code](https://www.promptarmor.com/resources/phishing-in-databricks-genie)** | A malicious uploaded skill created an HTML report containing tenant data. **Viewing the expanded results** triggered browser-side exfiltration and displayed a phishing modal. Compute egress restrictions did not govern the browser; display isolation did not remove data already embedded in the report. The approval agent allowed the code, and personal-workspace skills bypassed the governed catalog. | **No fix stated:** Databricks treated malicious uploaded skills as the user’s responsibility and described auto-approval as outside its security boundary. |

## C. Code execution and software supply chain

| ID / product and reference | Finding and prerequisites | Status reported in the source |
| --- | --- | --- |
| **C01 · [Snowflake Cortex Code CLI](https://www.promptarmor.com/resources/snowflake-ai-escapes-sandbox-and-executes-malware)** | A README injection exploited incomplete shell parsing and an agent-controlled request for unsandboxed execution. Malware ran without approval, used cached Snowflake credentials, and demonstrated data theft and table deletion. A parent agent could subsequently warn about the command without recognizing that a subagent had already executed it. | **Reported fixed:** Cortex Code **1.0.25**, February 28, 2026. |
| **C02 · [GitHub Copilot CLI](https://www.promptarmor.com/resources/github-copilot-cli-downloads-and-executes-malware)** | Commands wrapped in an automatically allowed utility escaped validation of their actual subcommands and network destinations. A poisoned README consequently caused malware download and execution without approval. The detailed bypasses were **macOS-specific**; other OS and file-access issues were mentioned but withheld. | **No fix stated:** GitHub validated the behavior but classified it as a known issue without significant security risk in its February 26, 2026 response. |
| **C03 · [IBM Bob CLI and IDE](https://www.promptarmor.com/resources/ibm-ai-%28-bob-%29-downloads-and-executes-malware)** | **After the user always-allowed a benign command**, parsing defects let a malicious compound command download and run code. Additional IDE leakage paths used Markdown images, externally sourced images in Mermaid diagrams, and automatic JSON-schema fetching, sometimes before edit approval. Rendered images could also support phishing. | **No completed remediation stated:** research concerned the closed beta. The article cautions against extrapolating a narrow command allowlist into broad execution safety. |
| **C04 · [Codex automatic approval](https://www.promptarmor.com/resources/agentic-auto-review-approves-malware)** | A hidden instruction in a GitHub issue led Codex to request installation of a malicious package. **With agent-based approval enabled**, the reviewing agent approved elevated execution; the package’s installation script ran outside the sandbox with the user’s privileges. | **Design/configuration risk:** PromptArmor explicitly says this is not a security vulnerability. It demonstrates fallible delegated approval, not a broken deterministic sandbox boundary. |
| **C05 · [Codex project configuration](https://www.promptarmor.com/resources/openai-codex-psa-on-malicious-config-files)** | **Accepting workspace trust** loaded project MCP configuration that immediately ran attacker code outside the sandbox. The warning emphasized prompt injection without explaining startup execution. An already trusted repository could later acquire a malicious configuration through an update and reuse that trust. This path does not require the model to follow an injection. | **Intended behavior per vendor response:** report closed February 16, 2026. PromptArmor recommends administrative restrictions on MCP startup commands. |
| **C06 · [Claude Code marketplace plugins](https://www.promptarmor.com/resources/hijacking-claude-code-via-injected-marketplace-plugins)** | **Installing a malicious plugin** introduced hooks that rewrote permissions or approved tool calls. A bundled prompt then induced codebase exfiltration. Marketplace impersonation and limited vetting aided distribution. Full device takeover was discussed as a possible extension; an indirect one-shot reverse-shell chain was not demonstrated. | **No fix stated:** the demonstration concerns powerful plugin and hook capabilities and the trust granted at installation. |
| **C07 · [Anthropic skill scanner](https://www.promptarmor.com/resources/anthropics-skill-scanner-defeated-by-backdoored-skills)** | Backdoored skills passed scanning because their harmful payloads arrived later from external data. Unsanitized shell/HTML processing then enabled malicious execution or poisoned artifacts. Production tests exfiltrated uploaded files through the allowed Anthropic Files API. Some tested models noticed only after execution; one avoided the tested payload. | **No fix stated:** scanning approval did not establish runtime safety. This includes conventional code-injection flaws, even when the payload never entered the model’s context. |
| **C08 · [Microsoft skill security scan](https://www.promptarmor.com/resources/microsoft-scan-misses-1-million-malicious-skills)** | PromptArmor seeded **1,046,565** marketplace skills with benchmark attacks. The **static security scan** detected 10.7%; detection fell to 0.4% after obfuscation. Prose payloads and unsupported code types exposed further coverage limits. The study tested the static scan, not the complete combination of model review and behavioral testing. | **Control evaluation; no fix stated.** These are results on deliberately modified samples, not evidence that 99.6% of ordinary marketplace skills are malicious or that all payloads would execute. |
| **C09 · [Cursor MCP Apps](https://www.promptarmor.com/resources/securing-cursor-a-security-practitioners-guide)** | An unsanitized customer field in a reference MCP app produced hostile JavaScript in an interactive view. Cursor’s insufficient view isolation let it issue keyboard commands, open a terminal, and execute shell commands. A malicious or compromised MCP response was the prerequisite; this was a conventional injection/sandbox problem, not necessarily model persuasion. | **No fix stated in the guide:** disclosed March 4, 2026; triage closed it as out of scope March 24. The guide also flags persistent learned-rule poisoning and autonomous review/automation risks as broader concerns. |

| --- | --- | --- |
| **D01 · [Claude Cowork](https://www.promptarmor.com/resources/claude-cowork-exfiltrates-files)** | A malicious document induced upload of accessible local files to an **attacker-owned Anthropic account** through an allowed API endpoint. No separate approval was required. PromptArmor demonstrated the Cowork chain while crediting **Johann Rehberger** with discovery of the underlying Claude.ai egress issue. A malformed PDF also caused persistent errors in one conversation; injection-driven denial of service was proposed, not demonstrated. | **No fix stated for the demonstrated egress path.** The denial-of-service observation is limited to conversation failure, not a proven platform outage. |
| **D02 · [Microsoft Copilot Cowork messages](https://www.promptarmor.com/resources/microsoft-copilot-cowork-exfiltrates-files)** | A poisoned skill induced retrieval of pre-authenticated file-download links and insertion into external image URLs in Teams/email messages sent to the active user. Self-directed messages skipped approval. **Opening the compromised message** leaked download links, which the attacker could use to obtain files. | **Design/configuration risk:** no completed fix stated for this path. It is distinct from the two subsequently remediated sandbox bypasses below. |
| **D03 · [Microsoft Copilot Cowork file-sync service](https://www.promptarmor.com/resources/microsoft-copilot-cowork-sandbox-bypass)** | Malicious skill code abused a file-sync service **outside** the sandbox to contact an attacker, fetch commands, and return results. It could directly invoke connected MCP tools to read mail and files. Background execution continued after the user pressed stop. | **Reported mitigated:** Microsoft confirmed mitigation on August 19, 2026. |
| **D04 · [Microsoft Copilot Cowork AI gateway](https://www.promptarmor.com/resources/hijacking-copilot-coworks-ai-gateway-to-exfiltrate-files)** | A malicious skill reused the internal model gateway to create agents in Anthropic’s cloud with network-capable tools. Those agents transmitted document contents to an attacker, bypassing the originating sandbox’s network restrictions without approval. | **Reported fixed:** Microsoft confirmed remediation on September 2, 2026. |
| **D05 · [ZoomMate / Zoom AI](https://www.promptarmor.com/resources/attacker-takes-over-zoom-ai)** | A malicious skill ran code in an environment with unrestricted HTTPS access, enabling continuing command retrieval and exfiltration of accessible meetings, messages, and connector data. Pressing stop or closing Zoom did not terminate the demonstrated background process. The article also describes prompt injection as another delivery route. | **Design/configuration risk:** PromptArmor describes intended network capability, not a malfunctioning component. No fix stated; browser-integration reach was not confirmed. |
| **D06 · [Google Antigravity](https://www.promptarmor.com/resources/google-antigravity-exfiltrates-data)** | A poisoned integration guide induced collection of credentials and source code. A shell command bypassed the file-reading restriction for ignored files; a browser subagent then transmitted the data through a default-allowed logging service. The demonstration used recommended automatic execution settings and **enabled browser tools**. | **No fix stated:** PromptArmor treated vendor warnings as acknowledgment of the risk. Three additional non-browser leakage paths were mentioned without public technical details. |

## E. Misuse of delegated authority

| ID / product and reference | Finding and prerequisites | Status reported in the source |
| --- | --- | --- |
| **E01 · [Elastic agentic SOC](https://www.promptarmor.com/resources/elastic-agentic-soc-vulnerable-to-credential-theft)** | A phishing alert manipulated the agent into creating a workflow that fetched attacker instructions and delegated them to a subagent. The workflow minted and exfiltrated API keys and the workspace URL. Resulting access enabled tenant-data theft and rule modification within the victim’s privileges. Approval steps were left to the agent’s discretion. | **No fix stated:** disclosed August 23, 2026; the article reports no remediation despite follow-ups. Other described consequences include persistence, fabricated alerts, and deletion. |
| **E02 · [OpenAI Agent Builder via MCP](https://www.promptarmor.com/resources/data-exfiltration-in-openai-agent-builder-via-mcp)** | In a researcher-built sales workflow, a malicious Google Form response caused an agent to email Salesforce records to an attacker through Gmail. The workflow allowed tool calls **without human approval**. An added LLM jailbreak guardrail missed the injection; another agent recognized malicious instructions but forwarded them downstream. | **Design/configuration demonstration:** not a claim that every Agent Builder workflow is vulnerable. The tested guardrail used GPT-4.1-mini and its stated default confidence threshold. |
| **E03 · [ChatGPT for Google Sheets](https://www.promptarmor.com/resources/gpt-for-google-sheets-data-exfiltration)** | An imported sheet induced privileged Apps Script execution, bypassing the setting requiring approval for workbook edits. The script followed links and stole **12 accessible workbooks** in the demonstration. It could alter sheets, replace the sidebar with a fake assistant, and display phishing dialogs. Pressing stop did not stop scripts already running. | **Vendor-reported mitigation:** May 31, 2026 update says OpenAI removed the model’s Apps Script generation capability while reassessing sandboxing. The earlier unanswered-disclosure narrative is superseded. |
| **E04 · [Claude Dynamic Workflows permissions](https://www.promptarmor.com/resources/claude-dynamic-workflows-use-incorrect-permissions)** | On tested Claude Code **2.1.168**, workflow subagents inherited the session’s approval mode, including Auto or BypassPermissions, despite documentation promising restricted acceptEdits behavior. Operators could therefore authorize workflows under a mistaken understanding of subagent permissions. | **Observed behavior/documentation mismatch; no fix stated.** This is inherited authority, not proof that subagents gained permissions beyond the parent session. |
| **E05 · [Copilot Cowork model opt-out bypass](https://www.promptarmor.com/resources/skill-accesses-deepseek-despite-copilot-cowork-admin-opt-out)** | Skills called DeepSeek and Mistral through Cowork’s internal access path despite organization-level non-enablement. No user-supplied API key was necessary, and skills controlled the downstream system prompt. A built-in scanner rated the demonstrated skill low risk. Accessible models appeared Azure-hosted; the result does not establish transfer to overseas provider infrastructure. | **Governance gap; no fix stated:** an update says the DeepSeek setting disappeared while skill-based access continued. Hosting, contractual treatment, and billing implications were unresolved in the report. |

## F–G. Broader research, governance findings, and operational risks

These entries distinguish measurements and observations from threat models, configuration advice, and analysis of other parties’ incidents. They are not 23 additional confirmed product exploits.

| ID / reference | Classification and summarized finding | Evidence boundary |
| --- | --- | --- |
| **R01 · [Model susceptibility study](https://www.promptarmor.com/resources/open-weight-susceptibility)** | **Model robustness.** Across 9,800 trials, the tested open-weight group had 26.7% attack success versus 14.2% for the proprietary group: roughly 88% higher **relative** susceptibility. Cost-effective and flagship variants also differed substantially. | PromptArmor’s benchmark, model selection, and attack mix; not a universal rate or proof that every open-weight model is less secure. Detection/refusal text did not reliably mean an attack was prevented. |
| **R02 · [External packages and URLs in skills](https://www.promptarmor.com/resources/50-percent-of-skills-include-external-packages-and-urls)** | **Supply chain and data processing.** 52.1% of 1,046,413 analyzed skills referenced external packages or URLs. Examples included a malicious 76-skill family encouraging attacker-code execution, an API-key/prompt relay to a hardcoded IP, and document processing by downstream AI. External content can change after approval. | External references alone do not establish maliciousness or successful execution. The article separately cites 1,046,565 collected unique skills; preserve the distinction between collected and analyzed populations. |
| **R03 · [Connector changes](https://www.promptarmor.com/resources/claude-and-gpt-connectors-change-every-9-minutes)** | **Permission and capability drift.** 931 of 2,517 tracked connectors changed during the study; additions included 1,686 tools and 21 formerly read-only connectors gaining write tools. Descriptions, scopes, endpoints, and model instructions also changed. | The nine-minute figure is an aggregate cadence across the monitored ecosystem, not the update frequency of every connector. Changed metadata does not by itself prove exploitation. |
| **R04 · [Downstream AI in Claude connectors](https://www.promptarmor.com/resources/2-in-5-connectors-call-external-ai)** | **Unreviewed processing.** Of 487 connectors, 189 had tools judged likely to invoke another AI service, potentially changing retention, residency, human review, and model-governance assumptions. | Based on assessment of 7,517 tool definitions; “may call” is not runtime proof that every request uses external AI. |
| **R05 · [Claude telemetry study](https://www.promptarmor.com/resources/claude-cost-and-risk-otel-findings)** | **Credential exposure, autonomy, and consumption.** In a ten-person enterprise sample, 66 commands exposed plaintext credentials that persisted into 5,840 model calls, about 9% of calls. Half of tool calls occurred more than ten model steps after user input; 4% of sessions accounted for 65% of spending. | Observed behavior in 310,009 events over 30 days; not proof of attacker theft or a population-wide failure rate. |
| **R06 · [WebMCP](https://www.promptarmor.com/resources/what-is-webmcp-and-what-are-the-risks)** | **Tool governance and browser authority.** Sites can expose or change authenticated actions outside traditional connector approval. Tool descriptions/results can inject instructions, misleading capability labels can affect approvals, and compromised page scripts can alter tools. | Threat model and adoption analysis, not a disclosed exploit against every supporting browser or website. |
| **R07 · [Harvey for Outlook](https://www.promptarmor.com/resources/what-is-the-risk-of-harvey-for-outlook)** | **Email, memory, and document integrity.** Untrusted messages may influence drafts, links, folder placement, generated documents, memories, and connector actions involving privileged legal data. Sending email requires user approval, reducing that action’s exposure. | A threat model. The article uses attacks on other products to illustrate what Harvey must defend against; it does not demonstrate those same exploits in Harvey. |
| **R08 · [Claude for Legal](https://www.promptarmor.com/resources/claude-for-legal-risk)** | **Confidentiality and output integrity.** Combined skills and connectors can expose privileged material, redirect signature workflows, or poison redlines and briefings. The effective connector set includes other enabled tenant connectors, not just those packaged with the legal plugin. | Scenario analysis; the separate demonstrated Cowork file-exfiltration chain is D01. Manipulated legal conclusions are a distinct integrity risk even without data theft. |
| **R09 · [Connector risk model](https://www.promptarmor.com/resources/the-risks-of-connectors-in-your-ai-applications)** | **Combined authority.** Joining untrusted input, private data, and an outward action can create a harmful chain across otherwise legitimate services. “Read-only” searches still transmit queries, and downloaded attachments introduce additional parsing exposure. | General architecture analysis. Its Confluence-to-Zendesk example is an illustrative attack scenario, not a separately disclosed vendor incident. |
| **R10 · [Different Microsoft Copilots](https://www.promptarmor.com/resources/what-is-the-risk-of-each-microsoft-copilot)** | **Scope and feature drift.** Products sharing the Copilot name have different data access and actions. Email, coding, spreadsheet, and automation features require different assessments; built-in feature expansion can change previously accepted exposure. | Portfolio threat model. Specific Cowork, CLI, and preview findings are counted in D02, C02, and A10 rather than again here. |
| **R11 · [Domain allowlists](https://www.promptarmor.com/resources/what-domains-should-i-add-to-my-allowlist)** | **Overbroad egress trust.** Shared hosting, package registries, cloud wildcards, forms, and authenticated upload APIs can host attacker-controlled destinations within reputable domains. Domain approval alone does not constrain the receiving account or action. | Configuration analysis supported by demonstrated cases such as A01, A03, and D01; not a claim that every listed service is itself compromised. |
| **R12 · [Local model hosting](https://www.promptarmor.com/resources/local-models-do-not-stop-data-exfiltration)** | **Misplaced security boundary.** Local inference can reduce third-party processing, but tools and interfaces can still transmit malicious output. Self-hosting also transfers responsibility for model files, serving infrastructure, denial of service, and unbounded resource consumption. | Synthesis of existing cases, not an additional set of 20 independent discoveries. A network-isolated complete system has different exposure from merely local inference. |
| **R13 · [AI in spreadsheets](https://www.promptarmor.com/resources/ai-in-excel-and-google-sheets-prompt-injection-and-data-exfiltration-risks)** | **Formula/script integrity and egress.** Imported cells can steer agents into inserting external requests or running scripts. Traditional macro controls do not necessarily govern text interpreted by an AI assistant. Approval granularity and cross-workbook access matter. | Cross-product analysis. The demonstrated cases are A08, A09, and E03; product inclusion in the overview is not proof of an exploit in every named add-on. |
| **R14 · [Dynamic Workflows risk](https://www.promptarmor.com/resources/what-is-the-risk-of-claude-dynamic-workflows)** | **Autonomy and availability.** Persistent consent, broad tool allowlists, approval classifiers, and up to 1,000 subagents can magnify harmful actions and consumption. ## Findings that cut across the categories

These conclusions are a synthesis of the linked reports, rather than additional discoveries:

- **An apparently harmless read or display can send data.** Image rendering, link previews, schema fetching, and URL retrieval deserve the same scrutiny as explicit upload tools. Examples: A03, A06, A10, A11, and C03.
- **An approval must govern the consequential action before it happens.** Hidden formulas, pre-applied edits, unchecked subcommands, and agent-selected approval steps undermine that boundary. Examples: A07, A09, C01–C04, and E01.
- **Sandbox review must include adjacent services and receiving accounts.** The browser, file-sync service, AI gateway, and trusted API can each provide an exit. Examples: B03 and D01–D04.
- **Skills and plugins are software dependencies.** Bundled code, hooks, runtime downloads, and changed upstream content can invalidate a clean initial scan. Examples: C05–C09 and R02.
- **A normal final answer or a stop button does not establish containment.** Some demonstrations concealed completed exfiltration, lost subagent context, or left background processes running. Examples: A09, C01, C07, D03, D05, and E03.
- **Integrity and availability matter alongside confidentiality.** Unauthorized SOC changes, poisoned legal outputs, malicious memories or learned rules, limited conversation failure, and runaway usage belong in the assessment. Examples: C09, D01, E01, and R07–R08/R14.
