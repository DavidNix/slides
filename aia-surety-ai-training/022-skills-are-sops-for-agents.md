# Skills are SOPs for agents

A skill is a packaged procedure the agent loads when a task matches:

- Instructions for one kind of work, plus optional templates and reference files.
- Written once, kept somewhere the agent can reach.
- Pulled in only for the tasks it covers — like an SOP pulled from the drawer.

**A skill is an SOP the agent can read: same procedure, same output, every time.**

## Speaker notes

Anchor on what the room already knows. Every department has SOPs: how a claim file gets summarized, how a submission gets checked, how a letter gets formatted. A skill is that SOP, written so the agent can follow it. The room does not have to re-explain the procedure each time — the procedure travels with the work.

Premade skills ship with the product: an Excel skill that knows how to build a clean workbook, a Word skill that produces a properly formatted document. Ask for an Excel deliverable and the agent reaches for that procedure without being told.

One distinction worth 20 seconds if it comes up: **skills tell the agent how to do a kind of work; connectors let it access a system.** The agent uses both to pursue the task. (The freight-fraud demo guide in this repo shows the pair working together, if a deeper example is needed.)

Transition: "Skills can be shared or private — and either way, they do not fill up the window."
