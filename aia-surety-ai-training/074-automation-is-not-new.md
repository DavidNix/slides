# Automation is not new

- **Automation existed long before modern AI.** A fixed workflow follows predefined steps: rules, macros, scheduled jobs, approval chains.
- **An agent chooses the next step.** It uses a model to pick the action based on the current situation — the same access, more judgment.
- **Both are useful, and one application can combine them.**

Fetching information and acting automatically can save more work — while broader access increases what a mistake or an attack can affect.

**Whether a step is automated or delegated to an agent, the trade is the same: more convenience, more access to manage.**

## Speaker notes

Automation is not the threat; unbounded access is. A fixed workflow behaves the same on every run — payroll runs the same steps each cycle, and a mistake affects one predictable output. An agent adapts: triaging a claim file means deciding what to do next from what it finds. That adaptability is the value and the risk — a mistake can touch whatever the agent can reach, and an attack on the agent inherits that access.

The combination is the realistic pattern: automation for the fixed steps, the model for the branching decisions. Don't upgrade a solved task to an agent just because AI can.

Recap the section's habit before the wrap-up: for each pilot idea from the exercise, decide deliberately which steps stay fixed automation and which steps get model judgment — and what access each choice grants.
