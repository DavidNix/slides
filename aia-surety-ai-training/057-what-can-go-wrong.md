# What can go wrong?

- **Wrong output:** missing facts, invented requirements, incorrect amounts.
- **Wrong access:** more information than the task needs.
- **Wrong action:** a message, update, or deletion that should not happen.
- **Wrong influence:** hostile content redirects the task.

**Impact depends on what the system can reach and do.**

## Speaker notes

This closes the problems. Defenses start next.

Accidents and attacks cause similar harm. Both get worse when the system can act.

Examples: a summary omits a condition, a draft promises a false deadline, a document goes to the wrong person, an agent edits a record it should only read.

Provider privacy and attacker data theft are different risks with different controls.

Mapping: wrong access → least privilege. Wrong influence → approval and classification. Wrong action → permissions and the gateway. Wrong output → verification.

Transition: "Now the defenses, in the same order."
