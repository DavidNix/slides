# Treat memory as untrusted content

The rule from the document example applies to saved history too:

- **Review what the agent remembers** — memory is inspectable in the product's settings.
- **Clear it after anything suspicious** — a strange reply, or an action you did not expect.
- **Memory informs; it does not override.** Current, verified instructions win.
- **Keep it scoped** — per person and per task, not one shared brain for the whole team.

**Stored history is content, not authority.**

## Speaker notes

The habits are concrete and available in consumer tools today: ChatGPT and Claude both expose memory management in their settings, with per-item delete and a full reset. Show the settings on screen if the room has accounts.

Why review matters: memory is the only part of the agent's context that persists without anyone choosing to include it — which makes it the part nobody checks. A thirty-second memory review is proportionate to the risk.

Why scope matters: shared or broad memory multiplies blast radius — one poisoned fact reaches every task and every teammate that leans on it. Keep memory personal and task-bound unless there is a specific reason not to.

Tie back: this is the same principle as the document slide — content the agent carries is evidence to inspect, not authority to act on. Memory just changes the shelf life.
